# 九队通用战斗策略

这九份 `00-队伍名.txt` 直接使用原 TXT 的动作、参数与统一流程编译器，没有 TXT→逐队 JSON 重定向或逐队 C# 排轴。角色以 `scripts/bettergi-scheduler/element-party-presets.json` 为准。

源码迁移、编译/离线测试、安装与实机结果是不同证据。本说明不代表这些策略已同步到安装目录，也不代表真实游戏已验证。

## 生存、开场与失败

- 每场先通过 `call(开场,once=battle,required)`。失败或提前返回不写开场完成记录、不解锁后继；新场必须重新确认。
- 正常维护使用同名 `record/maintain/watch`。已足够的窗口直接复用，不重新切人、施放或延长记录；必要补盾只维护护盾，不重放全部后台和开场。
- 监视器与消费者使用同一份覆盖需求。短窗口不足以完成完整动作时，先维护或走声明保底；多个维护通道冲突时有界暂停较低优先级维护。
- `required` 只保护所属片段与明确依赖；关键 Q 未确认不能进入其后续站场，可选 Q 跳过不阻断独立普通输出。
- 水/雷/冰/火的主输出与保底按 Q 状态互斥选路，已选爆发执行失败才走 `onfail` 保底；治疗、后台增益 Q 与独立 E 保持各自条件，不把所有 Q 机械改成输出二选一。
- 宏/移动/等待在可响应边界检查取消与结束。片段被放弃时先释放旧持续按键，再进入恢复；普通索敌不抢断已准入的喷射、落地或接球。
- 根循环保存本场记录；正常结束、失败、取消或重开场清理全部流程状态。独立物理 E 冷却参考可以跨场保留，不能替代本场开场成功。

旧合法 `e(hold,wait,refresh)` 仍支持，经兼容编译进入相同的确认/维护协议；不再依靠钟离名称或固定 20 秒专用执行分支。新策略使用显式具名维护以表达开场与独立通道。

## 数据与可观测边界

战斗开始读取技能库的固定快照，执行中不联网、不查询 SQLite。数值及语义规则有独立版本；来源变化后未复核规则不继续获得原有机制能力。同步失败/取消保留上一有效数据，用户修正与个人资料不被来源同步覆盖。

设置入口：**设置 → 自动战斗 → 技能知识库**。可查看版本/来源、同步公开数据、取消同步，以及导入已核验的机制规则或个人资料。命令行说明见 `Tools/SkillCatalogSync/README.md`；脚本入口为 `dispatcher.syncCombatSkills()`、`dispatcher.readCombatSkillStatus()` 等现有 dispatcher 扩展。

九队内置的 `timing(离线护盾,cd=12,duration=20)` 只是缺库时的策略估计兜底。有适用且已核验的数据库/用户覆盖字段时优先使用后者，冲突会诊断。普通作者无需逐条填写 CD、时长、技能 ID 或内部预算。

心海水母刷新和娜维娅附魔要求相应已解锁被动资料。未知条件不自动当作已解锁：水母走 E 替代，娜维娅走普通短打。只有已在游戏内核对时才导入个人资料，例如：

```json
{"CharacterKey":"navia","UnlockedPassives":["navia.passive1"],"Reason":"已在游戏内核对解锁"}
```

必须区分：

- E/Q 施放确认不等于命中、实际产球、接球或结晶满层；那维莱特来源事件后的水滴仍是保守估计。
- 技能有效时间不等于实测盾耐久、目标标记仍作用于新目标或角色仍在增益范围内。可靠失效证据会撤销旧覆盖；缺传感器时不编造强证据。
- Q 未亮不等于缺能；满能但 CD 中不继续充能。自动供能需要相应可信维度，Unknown 走跳过/保底。
- 观测只对当前可识别的角色/状态有效。后台血量、资源增量及稳定目标/范围身份不可用时保留 Unknown。

## 最小写法

```text
timing(离线窗口,duration=8)
record(战术窗口,timing=离线窗口)
琴 attack(0.5,keep=战术窗口)
```

```text
segment(开场,define) {
    钟离 e(hold,wait,required,record=护盾)
}

call(开场,once=battle,required)
琴 attack(0.5)
```

`segment(开场,define) { ... }` 只定义，遇到 `call(开场)` 才执行；`segment(开场) { ... }` 在当前位置直接执行。`define` 不决定是否循环或只执行一次。

常规 `call(片段)` 默认返回下一条，花括号片段结束后默认返回；需要片段成功记录时写在头部，如 `segment(开场,define,record=开场完成) { ... }`。旧 `segment(start,...)/segment(end)` 继续兼容。只有需要重检入口时才写 `resume=entry`，不必逐条填写内部过程身份、代次或输入归属。

## 安装与配置边界

同步工具会校验当前发布程序、增强流程源码的新旧及技能资源一致性，不能把新 TXT 单独安装到旧引擎。默认预览；真正同步、发布或启动程序需要另行明确执行。

配置同步不创建或重命名游戏内队伍。运行配置队伍功能前，游戏中应有相应同名队伍；切队失败应停止。矿物与采集配置不修改 TaskOrder、采集目标或本场运行记录。七元素路由仍为 `矿物,火,水,风,雷,草,冰,岩`，普通采集队单列为“采集”。
